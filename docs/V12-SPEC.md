0. Principles for all of v1.2
	•	One source of truth for money: every riyal that moves is a Transaction. Agreements, salaries, إضافة items and reminders are layers above the ledger; none holds its own balance.
	•	Attach, don't duplicate: a transaction may link to a party, an إضافة item, and/or an instalment; totals are computed from linked transactions.
	•	Establishment scope everywhere via requireX() and the scoping-gate test. ADMIN never sees establishment data, old or new.
	•	Owner-first UX: any screen in two taps; new sections collapsed until first used.
	•	Existing rules stay: month locks, soft deletes, audit on every mutation, canEdit for staff, no enumeration, generic errors, Western digits, all copy in ar.ts, زخم theme with v1.1d motion, print style for anything printable.
	•	Migrations expand-only; the live release keeps working while a migration is applied.

2. v1.2a — delivered and approved
2.1 Party: name, type عميل/مورد/موظف/أخرى, phone, email, notes, active. Type tabs; balances لنا/علينا count agreements only. Deactivate when it has history; delete only when unreferenced.
2.2 إضافة (Project): name, description, optional budget, start/end, status جارٍ/مكتمل/ملغى; list with spent/remaining/status; detail with own ledger, totals by category, budget bar, «تسجيل تكلفة» (form opens as صادر with the item pre-attached), printable summary.
2.3 Transaction gains optional partyId, projectId, instalmentId; form has a party dropdown («أخرى» keeps free text) and optional «ضمن إضافة»; ledger shows party and إضافة chip.
2.4 Plan: party, direction with wording by type («سيدفع لنا»/«سندفع له»), title, total, category, start date, reminderDays default 3, status قادمة/جارية/مكتملة/مؤرشفة/ملغاة, notes. Schedule: N at أسبوعي/شهري/كل N يوم or custom rows; live preview; must sum to total. Instalment: dueDate, amountDue, amountPaid, status قادمة→مستحقة→متأخرة / مدفوعة جزئياً / مدفوعة; countdown text.
2.5 Payments: «تسجيل دفعة» pre-fills and links; partial → جزئياً; overpayment rolls forward; excess beyond total shows an amber warning; edit re-allocates, delete un-pays; month locks apply; cancel only if nothing paid, else archive (writes off remainder); edits touch unpaid instalments only; owners manage plans and parties; staff with canEdit may only record payments.
2.6 Pages: الاتفاقيات list with filters; plan detail; المستحقات (today + 6 days and overdue, both directions, totals, quick pay); party page = printable كشف حساب with running balance; staff home «المستحقات» card for canEdit only (overdue + 7 days, max 20, party / amount without sign / date / pay button); staff payment form shows only party, remaining, rollover note; staff without canEdit get the form plus a not-allowed message.
2.7 Confirmed limits: 20M SAR per entry; badge updates on navigation; statement ordering quirk after archive.
3. v1.2b — الموظفون / الحضور
3.1 Profile: every employee is a Party of type موظف. Fields: job title, hire date, optional end date, basic salary, allowances list (سكن/نقل/أخرى), pay day, work schedule (work days default Sun–Thu, start/end time, grace minutes), notes. Optional link to one STAFF login of the same establishment; the link grants exactly: self check-in/out, view of own attendance month, view of own payslips and own salary instalments — nothing about other employees. Not stored: ID/iqama, IBAN, date of birth, photos, documents (later item requiring encryption at rest, masking, audited reveal).
3.2 Salary as a plan: saving a profile creates a payable plan «راتب شهري» via the v1.2a mechanism — one instalment per month on the pay day, amount basic + allowances, category رواتب; appears in المستحقات علينا; paid with «تسجيل دفعة»; the employee page has «صرف راتب» opening the current month's instalment. Salary changes affect future months only. An end date in the past stops generation and archives the plan. Salary payments are transactions: month locks apply.
3.3 Attendance: monthly grid (employees × days) and a daily sheet saved in one action. Statuses حاضر/متأخر/غائب/إجازة/عن بُعد/عطلة; عطلة pre-filled from the schedule; non-work days never count as absent. Times optional; with a check-in time and a grace, «متأخر» is computed and owner-overridable; with both times, hours are computed. Edited by the owner only — staff canEdit does not apply. Linked staff self check-in/out records times only for their own row using the server clock; status is derived from the times; staff cannot set غائب/إجازة/عن بُعد. Month locks do not apply to attendance.
3.4 Monthly sheet per employee: totals per status, hours, and a manual deduction with reason that reduces that month's salary instalment. Payslip print per employee per month: basic, allowances, deductions with reasons, net, payment date/method, establishment header, footer «هذه القسيمة ليست مستنداً رسمياً لحساب الأجور». Printable monthly attendance grid.
3.5 Privacy: salary-linked entries (payments of a salary plan's instalments, and any رواتب entry linked to an employee party) are hidden from every staff view — ledger, search, the staff المستحقات card, any staff-reachable list or export — except the employee's own payslips and own salary instalments on «حضوري». Aggregate totals on the staff dashboard may include them. A test asserts a staff session never receives another employee's salary-linked row. ADMIN sees nothing.
3.6 Out of scope: payroll calculation, GOSI, WPS, end-of-service, leave balances, location check-in, notifications.
4. v1.2c — التذكيرات والتقارير
4.1 Daily owner email digest to the owner's login email via Brevo, containing: instalments overdue, instalments due within each plan's reminderDays window, and anything due today or tomorrow; both directions. Settings › التذكيرات with hour and on/off. Triggered by GET /api/reminders/run protected by a new secret CRON_SECRET (in .env.example and render.yaml as sync: false; absent → 503, nothing else breaks). At most one digest per owner per day regardless of how often the endpoint is called. README note for a free external daily ping.
4.2 Client reminders: explicit per-party opt-in; email via Brevo or a copy-ready WhatsApp text; every send is an explicit owner action and audited; never automatic.
4.3 Reports: aging ٠–٣٠/٣١–٦٠/٦١–٩٠/أكثر for both directions, لنا first; party statement to Excel and PDF in the existing styles; «بحسب الجهة» filter on existing reports.
