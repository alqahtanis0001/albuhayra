## A. Home page — agent `home` (owns src/features/dashboard/**, src/app/(owner)/owner/page.tsx, src/components/Wheel*.tsx new)
A1 Overview wheel «نظرة شاملة على المنشأة», directly under the four money cards. Built from the mock, hand-written SVG, no library:
   - Centre: الرصيد الإجمالي + «الصافي ±X · ↑/↓ N٪» (same values as the existing cards).
   - Ring 1: this month وارد (green) / صادر (red), arcs proportional.
   - Ring 2: this month's OUT by category, top 5 + «أخرى» (same data as the donut).
   - Ring 3: commitments: لنا من العملاء (sum of positive party balances), علينا للموردين (sum of negative), رواتب الشهر (SALARY instalments due this month) — read-only fields added to getOwnerDashboard.
   - Dial: next 30 days clockwise from today (black dot «اليوم»): one dot per instalment due (fixed plans + salary instalments), size by amount (hit area ≥ 22 px via an invisible larger circle), green = لنا, red = علينا, gold = salary, hollow red = overdue (overdue dots sit just before today). Max 40 dots; beyond that, cluster by day with a count.
   - Animation: rings draw in order 1 → 2 → 3 → dial, ≈0.7 s each with the mock's delays; the matching explanation row lights up as its ring finishes; static under reduced-motion; the final still frame is complete for no-JS and print.
   - Four numbered explanation rows under the wheel, wording from the mock, values live. They are also the text equivalent for screen readers and print.
   - Tap/click: a segment, a dot, or a row focuses it (others dim to 18 %), the centre shows its name and amount; «إظهار الكل» clears; «إعادة العرض» replays. A second tap on a focused segment navigates: ring 1 → /owner/transactions?direction=…&from=&to= (this month); ring 2 → the ledger filtered by that category this month; ring 3 لنا/علينا → /owner/parties?type=…; رواتب → /owner/staff; a dot → that plan's page (salary dot → the employee page). Keyboard: segments are focusable buttons with aria-labels.
   - Empty establishment: rings in --track grey with «لا توجد بيانات بعد» in the centre; no animation.
   - Tests: arc angles sum to 360 − gaps, minimum visible arc, event day → angle mapping incl. overdue placement, dot sizing bounds, cluster rule, focus/dim state, navigation targets, empty state, ring 3 sums equal listParties totals — a mutation for each.
A2 One «يحتاج انتباهك» card replaces the overdue strip, WeekDues and the join-request notice: rows for overdue instalments, this week's instalments (لنا/علينا totals), pending join requests, and «الرواتب بعد N يومًا» when pay day is within 10 days. Each row links. Hidden when empty. Count badge in the heading.
A3 «التفاصيل والرسوم» disclosure holds: six-month chart (with waterfall tab), expense donut, balance by method, الأنشطة الجارية. Closed by default on phones, open on ≥ md; remembered per device (localStorage, EntryDetails pattern). Print shows it open.
A4 آخر الحركات shows 5 rows + «عرض الكل». Quick actions and the first-run card stay as they are.
Home order: quick actions → first-run card (if any) → 4 money cards → wheel → يحتاج انتباهك → آخر الحركات → التفاصيل والرسوم.

## Decisions (D1…; appended during the release)

D1. **Dark mode is in scope** (user's ruling 2026-10-11, C1); CLAUDE.md "Out of scope" now reads "dark mode until v1.5" and its precedence sentence names this file.
D2. **Ring 3 definitions** (lead, CP-A). «لنا من العملاء» = Σ `owedToUsHalalas` over `listParties(establishmentId)` (every party type); «علينا للموردين» = Σ `owedByUsHalalas` over the same rows **whose type is not `EMPLOYEE`** (an employee party's unpaid salary instalments are already «رواتب الشهر» — counting them twice would overstate what is owed); «رواتب الشهر» = Σ (amountDue − paid) of unpaid instalments of OPEN `SALARY` plans whose `dueDate` falls in the current Riyadh month. Open-ended plans stay outside لنا/علينا (V14 D10). The test pins: ring 3 لنا equals Σ of `listParties()` `owedToUsHalalas`, and علينا equals Σ of the non-employee rows' `owedByUsHalalas`, on the same fixture.
D3. **Dial geometry** (lead, CP-A). Day `d` ∈ [0, 29] (0 = today, Riyadh) sits at angle `360·d/30`, clockwise from the top (the «اليوم» dot at 0°). Overdue dots (unpaid, `dueDate < today`, OPEN non-OPEN_ENDED plans) sit in the arc just before today, `[−14°, −2°]`, most overdue furthest from today, evenly spaced. Visible radius `r` = 4 + 6·√(amount / max amount on the dial), clamped to [4, 10] viewBox units; every dot has an invisible hit circle of r = 14 viewBox units (≥ 22 CSS px whenever the 400-unit viewBox renders ≥ 315 px wide — the wheel's min width is set so it always does). Kinds: `IN` non-salary → green, `OUT` non-salary → red, `SALARY` → gold, overdue (any kind) → hollow red. More than 40 dots (overdue included) → one dot per day with a count label, sized by the day's sum, coloured by the day's largest kind; overdue collapse to one hollow cluster. Dots never overlap the today marker.
D4. **Navigation targets** (lead, CP-A). Ring 1 وارد → `/owner/transactions?direction=IN&from=<month start>&to=<month end>`; صادر → `direction=OUT`. Ring 2 category → `?direction=OUT&categoryId=<id>&from&to`; «أخرى» → `?direction=OUT&from&to`. Ring 3 لنا → `/owner/parties?type=CUSTOMER`; علينا → `/owner/parties?type=SUPPLIER`; رواتب → `/owner/staff`. Dot → `/owner/plans/<planId>`; salary dot → `/owner/staff/<employeeId>`; a cluster dot → `/owner/dues`. A row never navigates (it focuses its ring; the centre shows the ring's total).
D5. **Focus model** (lead, CP-A). First activation of a segment/dot focuses it; activating the focused one again navigates; activating another moves focus; a row focuses its whole ring; «إظهار الكل» and Escape clear. Segments and dots are buttons: each is an SVG `<g role="button" tabindex="0" aria-label="…">` (or an HTML button overlay, builder's choice) with Enter/Space handled; navigation uses `router.push`. The explanation rows are real `<button>`s. Dimming is opacity 0.18 on non-focused marks.
D6. **Animation is CSS only** (lead, CP-A): `pathLength="1"` + `stroke-dashoffset` keyframes with the mock's delays (ring 1 at 0 s, ring 2 at 0.8 s, ring 3 at 1.6 s, dial at 2.4 s, each segment +0.12 s, ≈0.7 s per draw); rows light by a CSS opacity animation on the same delays (+0.3 s) — no timers. The resting state of every element is the final frame (animations use `both`/`forwards` from a visible end state), so no-JS, print (`animation: none`) and reduced motion all show the complete wheel with every row lit. «إعادة العرض» re-mounts the SVG (React `key`).
D7. **Wheel split**: pure geometry in `src/features/dashboard/wheel.ts` (server-safe, tested), the interactive shell in `src/components/Wheel*.tsx` (client), data computed on the server and passed as plain props; the client imports types and small constants only.
D8. **«يحتاج انتباهك» rows and badge** (lead, CP-A). Rows, in order, each shown only when non-empty: (1) overdue — «{n} أقساط متأخرة» with لنا/علينا totals → `/owner/dues`; (2) this week — «أقساط هذا الأسبوع» with لنا/علينا totals → `/owner/dues`; (3) pending join requests — the requesters' names → `/owner/staff/logins`; (4) salaries — the next unpaid SALARY instalment of an OPEN plan due in [today, today + 10] → «الرواتب بعد N يومًا» («الرواتب اليوم» at 0) → `/owner/staff?pick=salary`. The heading badge counts the rows shown. The card prints (it is content, not chrome). `OverdueStrip`, `WeekDues` and `PendingJoinNotice` leave the home; their files may be deleted or reused by `home`.
D9. **«التفاصيل والرسوم»**: native `<details>`; initial state = the per-device stored choice, else open at ≥ 768 px and closed below (decided on the client after mount; server renders closed and a CSS rule shows the body at `md` until hydration so desktop never flashes closed). Print: `@media print` shows the body whatever the state and hides the summary's chevron.
D10. **Recent entries on the home**: 5 rows (the dashboard read's `RECENT_COUNT` → 5) + «عرض الكل» → `/owner/transactions`.
D11. **Theme mount points**: `theme` owns `src/app/layout.tsx` and writes `data-theme="light|dark"` (absent = system) on `<html>` from the `theme` cookie, plus `color-scheme`; `nav` owns `TopBar.tsx` and mounts `<ThemeToggle />` (one import, one element) from the component `theme` delivers. No inline script (CSP nonce) — "system" is pure CSS (`@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) { … } }`), as in the mock.
D12. **Hex → token in shared files**: `theme` replaces hard-coded colours everywhere except `src/features/dashboard/**`, `src/app/(owner)/owner/page.tsx`, `src/components/Wheel*` (home) and `src/components/chrome/**` (nav); for those it sends the owner the exact list and the owner applies it. Token-lint allow-list (no CSS custom properties possible there): `src/app/globals.css` (the token file), `src/app/api/export/**` (Excel cell styles), `src/lib/mail/**` (email HTML), `src/app/layout.tsx`/`public/manifest.json` `themeColor`, and test files.
D13. **Token layer first**: `theme` delivers C1 (tokens + dark values, no component changes needed) first; the lead commits it (`v1.5: token layer`) and pushes the branch; `home` and `nav` start with logic, routes and tests, and build visuals on the tokens once told the layer has landed. New colours in their code use tokens (`var(--color-…)` or Tailwind token classes), never hex.
D14. **B2 URLs**: `/owner/transactions?tab=reports` (sub-tab «حسب التصنيف», default) and `/owner/transactions?tab=reports&report=aging`; the report's own query (`from`, `to`, …) is kept. `/owner/reports?<q>` → `/owner/transactions?tab=reports&<q>`; `/owner/reports/aging?<q>` → `…&report=aging&<q>` (server `redirect`). The Excel export route and its links are unchanged. السجل highlights for `/owner/reports*` (`also`).
D15. **«صرف راتب» row visibility**: the owner layout reads one scoped boolean (`hasActiveEmployees`, a count > 0 over active employees) and passes it to the nav's `addRows`; the scoping gate gets a case. Pick mode lists only active employees with a SALARY plan; tapping one opens the same URL the employee page's «صرف راتب» uses for the current month's instalment; an employee whose current month is already paid shows «مدفوع» and links to the employee page instead.
D16. **What dims on focus follows the mock** (lead, after watching it): a focused segment keeps its whole ring at full opacity and dims every other ring and the dial to 0.18 (a focused dot keeps the dial lit); the centre shows the focused segment's name, amount and ring name. "A second tap on a focused segment" means the same segment (tracked by id), not any segment of the focused ring.
D17. **The wheel lives in the app's own `Card`** (squared corners, IBM Plex Sans Arabic, the card's title style): the mock's 14 px radii, its font link and its sample note line are not copied — "v1.5 never restyles". At 390 px the mock's SVG renders 324 px wide; the app's card must leave it ≥ 315 px (D3).
