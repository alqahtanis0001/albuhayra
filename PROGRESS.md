## How to run
```
cp .env.example .env     # DATABASE_URL, SESSION_SECRET, SEED_ADMIN_EMAIL, SEED_ADMIN_PASSWORD
npm install              # then: npm approve-scripts --allow-scripts-pending  (prisma + esbuild need their install scripts)

npm run seed             # creates the ADMIN account (idempotent)
npm run dev              # http://localhost:3000
npm run build && npm test
npm run typecheck        # tsc --noEmit, not part of build
```
`DATABASE_URL` is read by `prisma.config.ts` (which loads `.env` via dotenv) for migrate/seed, and by `src/lib/db.ts` at runtime. `prisma generate` and `npm run build` work without it.

- 2026-09-29 — **Two encoded exceptions in the scoping gate, approved; any third needs a lead Decision.** `changeOwnPassword` scopes by the session's own user id (an ADMIN has no establishment) and `allocateJoinCode` probes join-code uniqueness globally by nature. Both are **encoded narrowly in `scopeFailure`** rather than handled by excluding their files, which is the right trade: an excluded file stops being watched entirely, while an encoded exception is machine-checked — widen the `select` or add an `establishmentId` and it fails. Note this is not in tension with rule 2b's "ban `update` outright, no exceptions": that banned *per-call* waivers of the form "this one is safe because of the line above it", which need a human to re-verify at each site and rot. A typed, narrow, machine-checked exception is a rule, not a waiver. The governance risk is the third and fourth exception added casually, so **each new one requires a logged Decision** stating why the scope cannot apply and how the encoding is bounded — **and a harness case pinning its bounds.** The reviewer found the hole in the Decision rule alone: a *new* exception is visible in a diff and triggers the rule, but the silent **widening** of an existing one adds no exception, triggers no Decision, and reads as a small simplification. Dropping `Object.keys(select).length === 1` from the join-code exception, or relaxing `where.id === USER` to `typeof where.id === "string"` in the self-write exception, widens the gate with no test failing. Only a pinning case catches that. Note the asymmetry that makes this easy to miss: the tenant rule is protected by a *foreign id existing in the fixture to fail against*, and the self-write rule had no equivalent until an `OTHER_USER` constant was added beside `OTHER_EST`.

## Gotchas
- Whole app is RTL: Tailwind logical utilities only (`ms-`, `me-`, `ps-`, `pe-`, `text-start`).
- Every query is scoped by `establishmentId` from the session — never trust an id from the client.
- Month lock is enforced in `src/features/locks/assertUnlocked.ts`; every transaction mutation calls it. (Not written yet — `backend`.)
- `src/lib/validation.ts` is the backend/frontend contract; only the lead changes exported names.
- Error contract: every zod message and every `ActionResult.error` is an **i18n key** (`err.*`), never Arabic text. `errorMessage(key)` in `src/i18n/ar.ts` resolves one for display. Use `invalid(zodError)` in actions so every failure has the same shape.
- Dates: `@db.Date` columns round-trip through `isoToDate` / `dateToISO`, which read and write in **UTC** on purpose. Only `todayISO()` and `currentMonthKey()` use Asia/Riyadh, and they are the only place "today" may be decided. Never use `new Date()` local getters on a stored date.
- `parseSAR` returns `null` rather than throwing, and rejects zero as well as negatives — an amount of 0 is never valid.
- Tests run with `TZ=Asia/Riyadh` (set in `vitest.config.mts`) so they do not depend on the machine's clock settings.
- `npm install` on a fresh clone leaves Prisma and esbuild uninstalled until `npm approve-scripts --allow-scripts-pending` runs; the approvals are recorded in `package.json` under `allowScripts`.
- **The proxy cannot import `src/lib/session.ts`** — that file is `server-only` and reads `cookies()` from `next/headers`, neither of which exists in the proxy runtime. It reads the session with `getIronSession(nextProxyCookies(request, response), …)` instead. The cookie name and TTL both sides need now live in `src/lib/sessionConfig.ts`, imported by both; do not re-inline them.
- **Never redirect a signed-in visitor away from `/login` on the cookie alone** — that is a loop, because the proxy sees only the cookie while authority lives in the DB, so a since-disabled user bounces `/login` → `/owner` → `/login` forever. The bounce that exists is safe only because of the `signedOut` marker `requireUser()` adds when it is the reason the visitor is there.
- **`updateCategory` refuses a changed `type`** (`err.categoryDirectionMismatch`): existing entries already point at the category and carry its direction, so renaming is the only safe edit.
- **`allocateJoinCode(client)`** is structurally typed rather than taking `Prisma.TransactionClient`, so `src/lib/joinCode.ts` stays dependency-free and unit-testable. Pass `db` or a `tx`. It throws after five collisions, so callers must catch and return a result.
- **The rate limiter is in-memory**, so it resets on deploy and does not span Render instances. Keys are `login:<ip>:<email>`, `signup:<ip>`, `join:<ip>`. It defends against one client hammering one instance, not against a distributed attempt.
- **`redirect()` works by throwing**, so a `try/catch` around one silently swallows the navigation and leaves the user on the form with no error. Every `redirect()` must sit outside the surrounding `catch` — in the auth actions the `catch` comes first, then the redirect. Not obvious from reading, so it is now a reviewer check.
- **Verify "nothing is static" from `.next/prerender-manifest.json`, not the build's route table** — the table omits `/_global-error`.
- **`activeHref()` in `src/components/chrome/nav.ts` picks the longest matching href**, so `/owner/transactions/new` highlights إضافة only, never إضافة *and* السجل. Exactly one `aria-current="page"` per nav.
- **`ConfirmDialog` is a native `<dialog>` + `showModal()`** — the platform supplies the focus trap and Escape, with no library. It does **not** close on a backdrop click, which is the safer default for a destructive confirmation.
- **Tailwind v4 tokens live in the `@theme` block of `globals.css`**: `--color-money-out` yields `text-money-out` / `bg-money-out` / `border-money-out`, and the `-soft` variants are the pale badge and stat-card backgrounds.
- **`getOwnStatus` was deliberately deleted, not lost.** It was written for a session-reading `/pending` before the `?as=` design settled, and `/pending` never called it — `getSession().role` covers the one thing that page needs. Withdrawn from `docs/BACKEND.md` and the file removed. Do not rebuild it; if a PENDING account ever needs a real status read, that is a new decision about what an unapproved account may hold.
- **When a report and the tree disagree, the tree wins — and `grep` for the symbol, not `ls` for the file.** This happened three times in one checkpoint: the action shape, the zzsmoke deletion, and a query reported present that was gone. An `ls` passes on an empty or renamed file; a `grep` for the exported name does not. The index is a third source that can disagree with both: a file can be deleted from disk and still be staged, so verify the **commit object** (`git ls-tree -r HEAD`, `git grep <symbol> HEAD`) rather than the working tree.
- **Never `git commit --amend`. New commits only.** Teammates verify a hash and hold it; an amend silently dangles every hash already in circulation and sends the team into mutual corrections. If a checkpoint commit needs a follow-up, make a second commit.
- **When assigning any task, send the reviewer the task brief at assignment time**, not when the work lands. The reviewer then checks the brief against the doc it summarises *before* code exists. The three highest-value findings in Checkpoint 1 were found that way rather than in review, and it is also what catches a lossy task summary.
- **A `@db.Date` and a `DateTime` need different serialisation helpers.** `dateToISO()` reads UTC getters, which is right for a stored calendar date and **wrong for an instant**: a month locked at 01:00 Riyadh is 22:00 UTC the day before and would display as the previous day. Instants (`lockedAt`, `createdAt`) go through `todayISO(instant)`, the Riyadh formatter. Getting this backwards produces an off-by-one-day that only appears between midnight and 03:00 Riyadh, which is close to untestable by hand.
- **No exported query return type may contain a `Date` or a Prisma `Decimal`** — it throws when a server component passes it to a client component. Converting one field is not the fix; sweep every exported shape, because the same break is usually latent in a sibling query. `LockRow.lockedAt` was caught by `frontend`; the identical bug in `StaffRow.createdAt`, which would have surfaced at W7, was found only because `backend` swept rather than patching the one it was told about.
- **The export route's 307-not-403 behaviour is reasoned, not tested.** `requires an owner before doing anything` asserts `requireOwner` was called; the mock resolves, so the refusal path is never exercised. The security property holds structurally regardless — `redirect()` throws, so the handler cannot fall through to building a workbook — and `backend` confirmed the status empirically against a running build, including via the prefetch path. But **do not cite that test as evidence for the status**; the property is safe, the specific status is inference plus a manual check.
- **When a validation rejection has to be echoed back into a form, keep the rejected values strictly separate from the values the page acts on.** `frontend` hit this on the 366-day report cap: echoing the rejected `from`/`to` back as the resolved range so the form could redisplay them meant the page would then **query the very span the cap exists to refuse** — turning a validation message into the timeout it was written to prevent. The shape that works: the safe fallback is what gets queried, and a separate `rejected: { from, to, toError }` is echoed into the form so the message sits under what the user actually typed. The general form: a rejected input may be *displayed*, never *used*.
- **A fallback that swallows a validation failure is worse than no validation.** The same parser originally fell back to the current month on *any* parse failure, so a two-year request silently returned a one-month report and the user met the real limit later, somewhere else, with no explanation. A fallback must be accompanied by the reason it fired.
- **The scoping-gate harness lets a canned response be a *function* of the call arguments**, so `findMany` can honour `skip`/`take`. Without that, no paging behaviour is testable through the mock at all — which is why the `pageTotals` criterion needed a harness change before it could be written.
- **An excluded file is indistinguishable from an overlooked one unless the comment names what covers it instead.** The admin exclusion in `scoping.test.ts` names `admin.test.ts` and states which rule applies there, which is what makes the absence legible as a decision rather than a hole. Hold every future exclusion to that standard.
- **A pin should fail for one reason, not three.** When `backend` widened each gate exception in turn, each widening failed **exactly one** case. The difference matters on the day someone drops a clause: three cases going red says "you broke the gate", one named case says "you dropped the `select` length check". Precision keeps a failure actionable a year later.
- **A gate that strips comments before checking needs a test that the stripper did not blank the file.** Otherwise every other assertion in the suite passes vacuously. `admin.test.ts` has that third case; it is the same hazard as a gate nobody has watched fail, one level down.
- **Route handlers should take a plain `Request`, not `NextRequest`.** `request.nextUrl` exists only on the latter and makes the handler untestable without constructing a Next-specific object; `new URL(request.url).searchParams` is identical at runtime and testable.
- **A client component needing a query's type needs a type-only re-export module, and that module may contain nothing else.** Query modules start with `import "server-only"`, so a client component cannot import them at all. `export type` is erased by TypeScript and is therefore the only safe content; the moment someone adds an importable *value* to such a file, the boundary stops being safe with nothing looking wrong. Write the prohibition in the file as a rule, not a description. The failure mode if it is missed is a build error rather than a silent leak — `server-only` throws — so a green build is real evidence here rather than a formality. Applies to W4 and W6 as it did to W2.
- **The cheap check is owed at the moment your word makes someone else act.** The reviewer's formulation, and better than either "verify everything" (too expensive to sustain) or "trust your teammates" (too loose). Believing a claim from whoever owns the file is fine. Filing a finding, writing a brief, or asking someone to change working code *on the strength of it* is the point where a `grep` is owed — because that is where being wrong costs someone else their time and gets attributed to their task.
- **Re-read immediately before asserting, rather than reading once carefully.** A fact about a tree several agents are editing has a shelf life measured in minutes, and no amount of care at time T survives an edit at T+1. This produced four apparent "mistakes" in Checkpoint 1-2 — the action shape, `zzsmoke`'s first deletion, `getOwnStatus`, and an `ar.ts` key — where **every individual read was accurate when made**. Triage them by whether the tree lies *loudly* or *silently*: a missing i18n key or a changed signature fails at `tsc` and costs minutes, while a file reported present that is absent, or a renamed money field paired with the wrong label, compiles and ships. Only the silent kind justifies the verification overhead.
- **Two kinds of attention, and neither subsumes the other.** The unscoped-aggregate risk was invisible from the UI and only a structural check could catch it; the retired-category bug was invisible structurally — the rule was self-consistent and enforced exactly as written — and only someone imagining a real owner's afternoon ("I cannot fix a typo on a two-year-old expense without rewriting its category") could find it. Keep both pointed at this codebase: tests and greps for the first, and walking a screen as a user for the second.
- **A green tree is not a clean tree.** An untracked file is invisible in `git diff` and will still be captured by `git add -A`. Before any commit: `git status --porcelain --untracked-files=all`, confirm `find src/app/api -name "route.ts"` returns only `health` and `export` (match on `route.ts` specifically — a colocated `*.test.ts` under `src/app/api/` is legitimate and not routable), scan `src` for temporary markers, and verify the **commit object** rather than the working tree. This is not hypothetical — an unauthenticated OWNER-session factory sat untracked in the tree during Checkpoint 1.
- **Next 16 is not the Next.js you remember, and its own docs ship in the repo:** `node_modules/next/dist/docs/` (start at `index.md`, App Router material under `01-app/`). Check there before trusting recalled API knowledge — the `middleware.ts` → `proxy.ts` rename in Phase 0 was exactly this trap. Read them from `node_modules`; do not let anything write guidance into `CLAUDE.md`.
- **Never append `t.common.currency` to a formatted amount.** `formatSAR()` already appends `ر.س`; doing both renders `1,234.50 ر.س ر.س`. `t.common.currency` exists only for a standalone label such as an input suffix.
- Arabic month names live **only** in `src/lib/dates.ts` (`MONTH_NAMES_AR` / `monthNameAr`), not in `ar.ts`. Import them; do not add month keys to `ar.ts`.
- The proxy does **not** see every request: its matcher excludes `_next/static`, `_next/image`, `icons`, `favicon.ico`, `*.png`, and — via the `missing:` clause — `next/link` prefetches. So prefetch responses carry no CSP header and no role routing. **Demonstrated, not assumed, on the export route:** signed out → `307 /login`; signed out *with* a `purpose: prefetch` header, so the proxy never ran → still `307 /login`, from `requireOwner()` itself; a forged well-formed sealed cookie naming a nonexistent user → `307 /login?signedOut=1` on both paths. So the prefetch bypass buys an attacker nothing where `requireX()` is doing the work, which is what `docs/BACKEND.md` says it should be. The Phase 0 note that this was "defence-in-depth only" was right, *and* it composed with a stray unauthenticated route into a real hole in Checkpoint 1 — so the lesson is that the proxy is never the gate, not that the bypass is harmless.
- Duplicate category names are prevented in application code against **active** categories only, not by a DB constraint — see the Decision above. A concurrent double-submit can still create two.
- Do not import `src/lib/session.ts`, `auth.ts` or `audit.ts` from a test — they are `server-only`. Test `permissions.ts` instead; that is why it exists.
