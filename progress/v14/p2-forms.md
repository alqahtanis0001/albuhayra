## Gotchas I found
- **Next's webpack resolves `.tsx` before `.ts`** (`node_modules/next/dist/build/webpack-config.js`: `['.js','.mjs','.tsx','.ts',…]`). A module `partyList.ts` beside the existing `PartyList.tsx` would resolve `./partyList` to the *wrong file* on a case-insensitive filesystem (the user's click-test machine) — the brief's name was unsafe, so the module is `quickPartyList.ts`. Rule: never name a `.ts` module as a case-variant of a sibling `.tsx`.
- Running vitest on files **outside the repo** works with the programmatic API when `root` = repo, `dir` = the scratch folder and `include` names the test file; resolve `vitest/node` through `createRequire(repo/package.json)` (a plain `import "vitest"` from a scratch script fails). Copy the *whole* feature folder — relative imports (`./rules`) are not aliasable.
- `renderToStaticMarkup` writes `selected=""` on the controlled option: match options with `[^>]*` after the value. `t.partyQuick.add` starts with `+` — escape i18n text before building a `RegExp` from it.
- Line budgets: count like `wc -l` (`trimEnd().split("\n")`), not `split("\n").length` (one more for the trailing newline).
- The `hidden` attribute on a `flex` container: Tailwind v4 preflight has `[hidden]:where(:not([hidden="until-found"])) { display: none !important }`, so `hidden` wins over `flex` — no extra class needed.
- `renderToStaticMarkup` runs no effects: the S7 pin is a render-path pin (a render with a spying `localStorage` sees no `setItem`) plus a static pin on the source (the only `rememberDetailsOpen(` call sits in `toggle`). An effect-level mutation would need a DOM renderer the repo does not have (C1).
- In a static-pin regex, count the *calls* (`rememberDetailsOpen(`): a bare import line has no paren — my first count was off by one.
- `vi.stubGlobal("localStorage", …)` + `vi.unstubAllGlobals()` in `afterEach` is enough in the node env; no jsdom needed.
